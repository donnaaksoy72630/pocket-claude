Дата: 2026-10-23. Репозиторий: этот (`main`). Исполнитель — Hoplite. Сборку на реальном iPhone и замеры делает владелец на Mac (там есть Xcode, iPhone 15 Pro Max, iOS 26.7).

3. Без нативного модуля `nativeCalls === false`, и iPhone идёт по запасному пути `JsSpeechEngine` (`expo-speech-recognition` + `expo-speech`). На нём было:

## 2. Цель

Звонок из открытого чата ведёт себя как обычный телефонный разговор: я говорю — он слышит и пишет текст, отвечает голосом, его можно перебить, **звонок продолжается при свёрнутом приложении и выключенном экране**, состояние звонка видно на экране блокировки/в статус-баре. Телефон при этом не греется заметно сильнее, чем при обычном голосовом звонке.

## 3. Требования

### 3.1 Нативный движок звонка (iOS) — главное

Локальный Expo-модуль `apps/mobile/modules/pocket-call` (Swift), реализующий **ровно** интерфейс из `modules/pocket-call/index.ts` (функции, события, поля). Если интерфейс нужно поменять — менять вместе с `src/speech-engine.ts` и тестами.

Файлы (все — в git, проверить `git ls-files apps/mobile/modules/pocket-call`):
- `ios/PocketCall.podspec`, `ios/PocketCallModule.swift` (определение модуля), `ios/CallEngine.swift`, `ios/CallKitBridge.swift`, `ios/PowerMonitor.swift`.

Поведение:
1. **Одна `AVAudioEngine` на весь звонок**, `AVAudioSession` = `.playAndRecord`, mode `.voiceChat`, опции `defaultToSpeaker`/`allowBluetooth(HFP)`/`allowBluetoothA2DP` по настройке «Speaker»; `inputNode.setVoiceProcessingEnabled(true)` (эхо- и шумоподавление). Движок не останавливается между фразами — это и удерживает приложение в фоне (`UIBackgroundModes: audio, voip` уже в `app.json`).
2. **Распознавание:** `SFSpeechRecognizer(locale: ru-RU)` + `SFSpeechAudioBufferRecognitionRequest`, `shouldReportPartialResults = true`, `requiresOnDeviceRecognition` когда `supportsOnDeviceRecognition`, `taskHint = .dictation`, `addsPunctuation = true`. Буферы — из одного tap на входе движка. Запрос пересоздаётся на каждую реплику (лимит ~1 мин на запрос), без остановки движка. Простой VAD по энергии сигнала + предбуфер ~1 с, чтобы не терять начало фразы.
3. **Синтез:** `AVSpeechSynthesizer.write(_:toBufferCallback:)` → `AVAudioPlayerNode` в том же движке (не отдельная сессия), голос — лучший установленный для языка (Premium > Enhanced > Default) или выбранный в настройках, скорость = `AVSpeechUtteranceDefaultSpeechRate`. Перебивание: голос пользователя (VAD) во время синтеза останавливает плеер (если включено «Talk over the answer»).
4. **CallKit** (`CXProvider`, `CXCallController`, `supportsVideo = false`, без push — звонок «исходящий», стартует из приложения): системный интерфейс звонка на экране блокировки, зелёная плашка/Dynamic Island, mute/end с экрана блокировки и AirPods, корректные удержания при входящем GSM-звонке (`AVAudioSession.interruptionNotification`). Аудиосессию активировать в `provider(_:didActivate:)`. Отключается настройкой «Show as a phone call»; без CallKit — тот же движок, фон держит `audio`.
5. **Фон и экран:** звонок не прерывается при сворачивании, блокировке, автоблокировке, смене маршрута (наушники/AirPods/динамик), обрыве и восстановлении сети. При возврате в приложение — тот же звонок, в чате все реплики.
6. **«Плашка» в приложении:** зелёная полоса сверху на любом экране приложения во время звонка (уже есть в `src/call.tsx`) — тап возвращает на экран звонка; на экране звонка — таймер, статус (слушаю / думает / говорит / пауза), живой текст распознавания.
7. **Ошибки — человеческим текстом** на экране звонка: нет разрешения (с кнопкой «Открыть настройки»), распознавание недоступно для языка, Mac/ПК офлайн, сеть пропала.

### 3.2 Голос

1. В Настройках → Voice calls: если для языка звонка нет Enhanced/Premium-голоса — подсказка «Скачай голос получше: Settings → Accessibility → **Read & Speak** → Voices → Russian → Milena (Enhanced)» и кнопка, открывающая Настройки iPhone. Учесть, что в iOS 26 раздел называется **Read & Speak** (раньше Spoken Content).
2. Язык звонка по умолчанию — русский, если в последних чатах пишут по-русски или в системе есть русская клавиатура; иначе язык интерфейса. Сейчас «auto» при английском iPhone выбирает английский — это главная причина «не понимает».
3. Ответ озвучивается по предложениям по мере стрима, без чтения markdown/путей/URL/кода (код — «скопировал в буфер» или «смотри в чате»).

### 3.2a Голосовой ответ — коротко, а не весь текст (добавлено 2026-10-23 после проверки этапа A)

Сейчас звонок зачитывает ответ целиком, включая блоки кода, таблицы, списки, пути. Нужно, чтобы голосом звучал **разговорный ответ**, а детали оставались в чате:
1. **Brain (голосовой режим, `apps/brain/src/session.ts`, voice note):** в звонке Claude отвечает так: первые 1–3 предложения — устный ответ по сути (как человек сказал бы по телефону), дальше — при необходимости подробности/код для чата. Код, команды, пути, ссылки, таблицы в устную часть не попадают; вместо них — «код скинул в чат» или «положил в буфер» (если просили).
2. **Телефон (`src/voice.ts`):** озвучивается только устная часть. Надёжная граница, не зависящая от честности модели: озвучка останавливается на первом блоке кода/таблице/списке длиннее 2 пунктов/заголовке и говорит «остальное в чате». Блоки ```…```, инлайн-код с путями/URL, markdown-разметка не произносятся никогда.
3. Длина устной части — не больше ~40 секунд речи; дальше «подробности в чате».
4. Если в ответе только код — сказать одной фразой, что это (например, «вот команда для PowerShell, она в чате»).
5. Тесты в `apps/mobile/test/voice.test.ts`: ответ с кодом, ответ-таблица, ответ только из кода, длинный ответ.

### 3.3 Логика разговора (`src/voice.ts`)

Уже есть и покрыто тестами — сохранить: не читать старую историю, слушать снова только после конца хода Claude, перебивание, «стоп», разрешения голосом «да/нет», «остальное — в чате». Добавить:
- задержка «я закончил говорить» ≈ 0,8–1,2 с, дольше после союзов (уже есть — проверить на русском);
- если Claude думает дольше 4 с — короткая фраза «секунду» или тон (не чаще раза в 8 с);
- метрики в лог звонка: время от конца фразы до первого звука ответа.

### 3.4 Холодный телефон (оптимизация)

Цели на iPhone 15 Pro Max, Release-сборка, замер Instruments (Time Profiler / Energy Log) делает владелец:
- открытый чат без активности: CPU < 3 %, 0 перерисовок/с;
- стрим ответа: CPU < 25 %, не больше 10 коммитов React/с на экране чата;
- звонок 10 минут с выключенным экраном: термосостояние не выше `fair` (`ProcessInfo.thermalState`), разряд не больше, чем у обычного голосового звонка;
- системный лог приложения в звонке: не больше 50 сообщений/с (было 6000).

Что проверить/сделать:
1. Никаких циклов перезапуска/таймеров без затухания (как было с распознаванием). Любой перезапуск — с backoff.
2. Во время звонка: лента/рилсы на паузе, видео не грузится, аватарки/картинки не анимируются; `freezeOnBlur` для скрытых экранов (уже есть — проверить).
3. Поток событий из нативного модуля: уровни громкости/VAD — не чаще 10 раз/с; частичные результаты распознавания — только при изменении текста.
4. `PowerMonitor`: при `thermalState >= serious` или Low Power Mode — автоплей видео выключен, частота опроса Activity снижена, анимации упрощены.

### 3.5 Android

Звонок на Android идёт через `JsSpeechEngine`; поведение и настройки — те же. Проверить, что исправленный backoff и язык по умолчанию работают и там.

## 4. Как работать

1. Новая ветка от `main`, **каждое законченное изменение — отдельный commit и сразу push** (чтобы ничего не потерялось, как в прошлый раз). PR в `main` после этапа.
2. После каждого push проверять, что всё нужное в git: `git status --short` пусто, `git ls-files apps/mobile/modules/pocket-call` содержит все Swift-файлы и podspec.
3. Swift в песочнице не компилируется — поэтому CI `.github/workflows/ios.yml` (сборка под симулятор на macOS) должен проходить; при падении — чинить до зелёного. Перед PR: `pnpm typecheck`, `pnpm test`.
4. В PR — что не проверено на устройстве; владелец собирает Release на Mac (`xcodebuild … -allowProvisioningUpdates`), ставит на iPhone и присылает системный лог звонка (`idevicesyslog -p Pocket`).
5. Этапы:
   - **A.** Нативный модуль: движок + распознавание + синтез на переднем плане (без CallKit). Готово, когда: звонок по-русски слышит и отвечает, перебивание работает, лог < 50 сообщений/с.
   - **B.** Фон и CallKit: звонок живёт при свёрнутом приложении и выключенном экране, системный интерфейс звонка, удержание при GSM-звонке, смена маршрута звука.
   - **C.** Голос и язык (3.2), **короткий устный ответ (3.2a)**, ошибки (3.1.7), логика (3.3).
   - **D.** Оптимизация (3.4) и Android (3.5).

## 5. Приёмка (проверяет владелец на iPhone)

1. Звонок из чата → «Привет, ты меня слышишь?» → текст появляется на экране звонка → ответ голосом Milena Enhanced по-русски.
2. Во время ответа сказать «подожди» → ответ прерывается, слушает.
3. Свернуть приложение и заблокировать экран → продолжить разговор 3 минуты → ответы приходят и звучат; на экране блокировки — интерфейс звонка, «завершить» работает.
4. Наушники/AirPods во время звонка → звук переключается, звонок не рвётся.
5. «Сделай скриншот» / «вставь в буфер …» → выполняется на ПК, Claude говорит результат.
6. 10 минут звонка с выключенным экраном → телефон тёплый, не горячий; лог < 50 сообщений/с.
7. Открытый чат без звонка 5 минут → телефон не нагревается.
