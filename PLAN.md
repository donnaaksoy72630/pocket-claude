**Статус:** план утверждён, работа идёт по часам ниже. После каждого часа — коммит и push в ветку PR, чтобы ничего не потерялось, если закончатся лимиты. Отметки «✅» ставятся в этом файле вместе с коммитом этапа.

## Что просили

1. **Смена модели из чата и в звонке.** Сказать «поменяй модель на Fable и поставь мышление на максимум» — Claude сам переключает модель и уровень мышления этого чата.
2. **Песочница на MacBook для каждого чата.** У каждого чата своя папка: там Claude работает и хранит файлы, которые остаются между сообщениями и перезапусками.
3. **Управление компьютером (computer use) как в Claude.** Через PocketClipboard на Windows Claude видит экран и знает его размеры, понимает, куда нажать, водит мышью, печатает, нажимает сочетания клавиш, открывает и закрывает окна, запускает браузер и PowerShell. Например: «напиши такую-то команду в открытый PowerShell», «открой браузер и посмотри, что не так со слайдом на сайте».

## Что уже есть в коде

- `apps/brain/src/session.ts`: у каждого чата долгоживущий процесс Claude Code (Agent SDK 0.3.303, CLI 2.1.303). Метод `configure()` уже меняет модель и мышление на ходу (`setModel` и `applyFlagSettings({effortLevel})`), но вызывает его только телефон: `/model` и `/effort` → `session.configure`. Сам Claude этого сделать не может. Список моделей берётся из `supportedModels()`, в запасном списке Fable нет. Алиас `fable` в CLI есть.
- Чаты на Mac работают в одной общей папке `~/Documents/pocket-workspace` (`DEFAULT_MAC_WORKSPACE`). Вложения кладутся в скрытую `~/.pocket-claude/inbox/<id>`. Каждая команда Bash спрашивает разрешение на телефоне. Встроенная песочница CLI (Seatbelt, `sandbox` в Options) выключена.
- В `apps/clipboard-agent` (PocketClipboard.exe) уже есть буфер и скриншот всех мониторов одной картинкой, через PowerShell и WinForms: протокол `screen.capture` → `screen.image`, инструменты `pc_*` в `apps/brain/src/pc-tools.ts`. Мыши, клавиатуры и окон нет. Есть пример долгоживущего процесса PowerShell с JSON-строками: окно-оверлей, `overlay/window.ts`.
- Разрешения проходят через `PermissionBroker`: телефон («Разрешить / Для чата / Запретить»), Telegram и звонок (там голосом «да»/«нет» даётся разовое разрешение).

## Этапы

### ✅ Этап 1 — Claude сам меняет модель и мышление (`apps/brain`)

- Новый модуль `chat-tools.ts`: MCP-инструменты на сервере `pocket` во всех трёх режимах (Mac, удалённый Windows, чат без файлов):
  - `chat_models` — текущая модель и уровень мышления, плюс доступные модели с их уровнями (из `supportedModels()` живого Claude Code, иначе запасной список);
  - `chat_configure { model?, effort? }` — `model` принимает значение или имя (`fable`, «Fable», `opus`, `default`, полный ID `claude-…`), `effort` — одно из `low|medium|high|xhigh|max|auto`. Если модель не поддерживает `max`, ставится её наивысший уровень и Claude говорит об этом.
- Применение: метаданные чата меняются сразу, и чипы модели и мышления на телефоне обновляются через `session.updated`. Живой процесс переключается, когда закончится текущий ответ: модель не меняется посреди хода с инструментами.
- Инструменты разрешены без вопросов. В подсказку всех режимов и в `VOICE_NOTE` добавляется: «просят сменить модель или мышление — вызови `chat_configure` и одной фразой скажи, что поменял».
- В запасной список моделей добавляется Fable.
- Проверка: тесты на разбор имени модели, понижение уровня, результаты инструментов и применение после хода.

### Этап 2 — песочница для каждого чата на Mac (`apps/brain`)

- Новые чаты на Mac (владелец, без выбранного проекта) получают свою папку `~/Documents/pocket-workspace/chats/<дата>-<id8>/`, где `<id8>` — первые 8 символов id чата. Это рабочая папка Claude Code. Файлы остаются между сообщениями и перезапусками, а после удаления чата тоже не стираются, на всякий случай.
- Память чата — файл `NOTES.md` в папке. Claude записывает туда, что нужно помнить: цель, решения, где какие файлы. При каждом старте процесса заметки (до 20 КБ) и список файлов папки попадают в системную подсказку.
- Вложения таких чатов сохраняются в `<папка>/attachments/`, а не в скрытый inbox.
- Seatbelt-песочница CLI (`sandbox.enabled`) для чатов на Mac:
  - Bash может писать только в папку чата (или в выбранный проект) и во временную папку;
  - сеть идёт через прокси: короткий список хостов для разработки разрешён сразу (GitHub, npm, PyPI), остальные хосты спрашиваются на телефоне (`SandboxNetworkAccess`), а «Для чата» запоминает хост, а не всю сеть;
  - команды внутри песочницы выполняются без вопросов (`autoAllowBashIfSandboxed`);
  - правки файлов в папке чата принимаются сами (`acceptEdits`), а в выбранном проекте спрашиваются, как раньше;
  - выход из песочницы (`dangerouslyDisableSandbox`) идёт через обычное разрешение на телефоне;
  - если песочница не поднялась, команды идут по-старому, с вопросами (`failIfUnavailable: false`).
- Старые чаты остаются в общей папке: их Claude Code привязан к ней, а перенос стёр бы контекст разговора. Отличаются по `engine.cwd`.
- Выключатель: `POCKET_SANDBOX=off` (переменная окружения brain).
- Проверка: тесты выбора папки (новый чат, старый чат, проект), сборки опций песочницы, заметок и вложений, ключей разрешений по хостам.

### Этап 3а — PocketClipboard: экран, мышь, клавиатура, окна (`packages/protocol`, `apps/clipboard-agent`)

- Протокол: `computer.act { requestId, action }` от brain к компьютеру и `computer.done { requestId, image?, display?, displays?, cursor?, windows?, text?, error? }` обратно. Новая capability `computer`.
- Хост — долгоживущий `powershell.exe -STA -File computer.ps1` с C#-классом через `Add-Type`. Класс компилируется один раз при старте, команды идут JSON-строками, как у оверлея. При падении хост перезапускается.
  - DPI: per-monitor aware v2, поэтому координаты везде в физических пикселях.
  - Экран: снимок одного монитора с нарисованным курсором, уменьшенный до 1280×800 (оптимум для computer use). Отдельный снимок области в большем масштабе (`zoom`). Список мониторов.
  - Мышь: `SendInput` — перемещение, клики левой, правой и средней кнопкой (двойной, тройной), нажатие и отпускание, перетаскивание с промежуточными точками, прокрутка по вертикали и горизонтали, модификаторы при клике.
  - Клавиатура: текст через `KEYEVENTF_UNICODE` (кириллица печатается при любой раскладке, `\n` → Enter), сочетания в стиле xdotool (`ctrl+shift+esc`, `alt+tab`, `win+r`, `Return`, `F5`), удержание клавиши.
  - Окна: список видимых окон (заголовок, процесс, монитор, свёрнуто или активно); активировать (с обходом блокировки переднего плана), свернуть, развернуть, восстановить, закрыть (`WM_CLOSE`).
  - Запуск: `Start-Process` для программы, файла или URL (`powershell`, `chrome https://…`, `notepad`, `ms-settings:`).
- Проверка: vitest на разбор ответов и протокол; синтаксический разбор скрипта через `pwsh` на Linux (ставлю в песочнице); живая проверка — на Windows при приёмке.

### Этап 3б — инструмент `computer` в brain (`apps/brain`)

- Инструмент `computer` в формате Anthropic computer use. Действия:
  - `screenshot`, `zoom`, `cursor_position`, `wait`;
  - `mouse_move`, `left_click`, `right_click`, `middle_click`, `double_click`, `triple_click`, `left_click_drag`, `left_mouse_down`, `left_mouse_up`, `scroll`;
  - `type`, `key`, `hold_key`;
  - а ещё `list_windows`, `focus_window`, `minimize_window`, `maximize_window`, `restore_window`, `close_window`, `open`, `switch_display`.
- Координаты Claude даёт в пикселях последнего скриншота, brain пересчитывает их в реальные по геометрии монитора. После каждого действия через ~0,5 с приходит свежий скриншот, и Claude видит результат.
- Разрешение: при первом действии в чате спрашивается «Claude управляет компьютером X в этом чате?» (на телефоне, в Telegram, голосом «да»), дальше без вопросов до перезапуска brain. Навсегда разрешить: `pocket-claude allow computer`.
- Подсказка:
  - сначала скриншот;
  - сочетания клавиш лучше кликов;
  - окна — через `list_windows`/`focus_window`, программы — через `open`;
  - перед необратимым (отправить, удалить, оплатить, закрыть несохранённое) — спросить пользователя;
  - в звонке — коротко говорить, что делаешь.
- Стоп (⏹ или kill-switch) прерывает действие, PocketClipboard отпускает зажатые клавиши и кнопки мыши.
- Проверка: тесты пересчёта координат, схемы действий, маршрута до компьютера, разрешения на чат, ошибок (компьютер офлайн, старый exe без `computer`).

## Решения и ограничения

- Computer use — только на Windows через PocketClipboard: туда указывают PowerShell и «наша программка». Computer use на самом Mac (`screencapture` + CGEvent) можно сделать отдельным этапом позже.
- Модель меняется после текущего ответа, а не посреди него: так не ломается ход с инструментами и блоками мышления.
- Песочница ограничивает только команды оболочки, как и задумано в Claude Code. Файловые инструменты Claude (Read, Edit, Write) по-прежнему проходят через разрешения: правки вне папки чата спрашиваются.
- Разрешение на управление компьютером одно на чат. Спрашивать каждый клик в звонке было бы невозможно.

### Этапы

#### Этап 1 — Windows-оверлей (`apps/clipboard-agent`)

- Окно 400×500 (DPI-scale) в правом нижнем углу над панелью задач, перетаскивается за шапку, положение помнится до перезапуска.
- Исправление дублирования: `ReadOnly` снимается внутри `Update-Window`; хвост стриминга переписывается на месте.
- Markdown: `parseMarkdown` в `client-core` получает заголовки, списки (`-`, `*`, `1.`), цитаты, жирный/курсив; старые потребители (`paragraph`/`code`) не ломаются. Оверлей рисует заголовки жирным крупнее, списки с маркером, цитаты приглушённо, код на подложке.
- Темы: `dark` (чёрный) по умолчанию и `light`; кнопка в шапке; агент сохраняет выбор в состоянии и присылает окну при старте (`op: 'theme'`).
- Клавиши: одиночный короткий Alt без других клавиш — скрыть; двойной Alt — показать; Esc — скрыть.
- Без лишнего: шапка (название чата, тема, ×), внизу «Copy reply» и «Copy code»; «Copied» на секунду; двойной клик по коду копирует его.
- Проверка: vitest модели оверлея, синтаксический разбор PowerShell-скрипта (`pwsh` на Linux, если удастся установить), сборка exe — на Windows вручную (`scripts/build-exe.sh` нужен `node.exe`).

#### Этап 2 — Brain: чат друзей и инструменты ПК (`apps/brain`, `packages/protocol`, `apps/clipboard-agent`)

- Протокол: `screen.capture {requestId}` → исполнитель, `screen.image {requestId, mime, dataBase64, error?}` обратно; capability `screenshot` у `PocketClipboard`.
- Exe: скриншот всех мониторов через PowerShell (`CopyFromScreen`), уменьшение до 1600 px по длинной стороне, PNG → base64.
- Инструменты Claude (MCP в процессе brain): `pc_clipboard_read`, `pc_clipboard_write`, `pc_screenshot`. Работают с компьютером чата (или компьютером пользователя по умолчанию); скриншот возвращается как картинка, Claude её видит. Разрешения не спрашиваются — это свой буфер и свой экран.
- Режим «чат без файлов» для чатов, привязанных к компьютеру без `tools`: Claude запускается на Mac в `~/.pocket-claude/users/<id>/` без встроенных инструментов, только с инструментами ПК. Снимается ошибка «Add a computer first» для друзей с одним exe. Один пользователь — один компьютер: выбирается автоматически.
- Проверка: тесты `users.test.ts`/`overlay.test.ts` + новые на маршрутизацию скриншота и режим без файлов.

#### Этап 3 — Telegram-бот (`apps/telegram-bot`)

- Постоянная клавиатура на каждом ответе: `📋 ПК → текст`, `📥 Текст → ПК`, `📸 Скриншот`, `💬 Новый чат`, `⏹ Стоп`, `ℹ️ Статус` (`💻 Компьютер` только если компьютеров больше одного). Никаких `force_reply`: режим «следующее сообщение — в буфер» хранится в состоянии и показывается подсказкой.
- Под каждым законченным ответом Claude — inline-кнопки `Код → ПК` (если есть код) и `Ответ → ПК`.
- HTML-рендер markdown (жирный, курсив, заголовки, списки, ссылки) с fallback в plain text; один ответ — одно сообщение (длинные делятся по 4000).
- Друзья: `/start <код>` → компьютер выбирается сам, статус показывает его имя и онлайн.
- Проверка: `bot.test.ts`, `chat.test.ts` (стабилизировать гонку `/start`), `render.test.ts`.

#### Этап 4 — Мобильное приложение: производительность (`apps/mobile`)

- Видео: `useCaching`, без keep-awake, только короткие ролики (≤ 3 МБ), пауза вне экрана и вне вкладки.
- Картинки: стабильные seed (фиксируются при первом запуске), размер 720 вместо 1080, `cachePolicy` disk.
- Стриминг: буферизация дельт в `ChatClient` (≈ 8 обновлений/с), подписчики получают только изменённые треды; экраны вне фокуса не перерисовываются.
- Хранилище: запись replay/unread только при изменениях.
- Списки: `windowSize`, `removeClippedSubviews`, `initialNumToRender` для ленты и чата.
- Проверка: `tsc`, `expo export` (android/web), ручная проверка на iPhone — у вас.

#### Этап 5 — Мобильное приложение: бренды и регистрация (`apps/mobile`, `apps/clipboard-agent`)

- Персоны: список брендов (Lipton, Nescafé, Jacobs, Starbucks, Red Bull, Coca-Cola, Borjomi, IKEA, Samsung, Tesla…) с иконкой и градиентом; чат получает бренд по хэшу `sessionId`, инбокс выглядит как переписка с разными компаниями.
- Приглашения: QR-код приглашения рисуется в приложении владельца (плюс «Поделиться ссылкой»); у друга после пейринга — экран «Подключи компьютер»: код для exe, шаг «Открыть Telegram» (`telegram.link`), статус «компьютер онлайн».
- Exe: `install` принимает одну вставленную ссылку `pocketclaude://pair?…` (relay и код внутри), показывает safety number без вопросов.
- Экран «Компьютеры»: один компьютер — без выбора, только состояние.
- Интерфейс спокойный: без ярких акцентов, единые отступы, тёмная тема приложения.

#### Этап 6 — Звонок помощнику (`apps/mobile`, `apps/brain`, `packages/protocol`)

- Кнопка «Позвонить» в шапке чата → экран звонка (имя бренда, таймер, «говорю/слушаю/думаю», «Завершить», «Без звука»).
- Речь → текст на телефоне (`expo-speech-recognition`: Apple Speech / Android SpeechRecognizer), конец фразы — ~1.2 с тишины; текст уходит как `message.send` с пометкой `voice: true`.
- Ответ озвучивается по мере стриминга по предложениям (`expo-speech`, системные голоса, русский/английский автоматически); новая фраза пользователя прерывает озвучку.
- Экран выключен — звонок продолжается: `UIBackgroundModes: ["audio"]`, аудиосессия `playAndRecord`, `NSMicrophoneUsageDescription`, `NSSpeechRecognitionUsageDescription`; Android — foreground-сервис записи.
- Brain: при `voice: true` добавляет Claude указание отвечать коротко, разговорно, на языке пользователя, после действий с ПК — одной фразой «сделал, вижу то-то». Инструменты ПК из этапа 2: «сделай скриншот», «вставь в буфер команду», «прочитай буфер».
- Проверка: `tsc`, `expo prebuild --platform ios` (проверка Info.plist), тесты протокола. Живой звонок — только на iPhone у вас.

### Принятые решения

- Речь обрабатывается на телефоне, а не на Mac: бесплатно, без ключей, без передачи аудио через relay и без фоновых процессов на Mac. Если на практике распознавание окажется слабым, запасной путь — `whisper-cpp` на Mac (аудио чанками по тому же протоколу).
- Друзья работают на Mac владельца только в режиме «чат без файлов»: Claude не видит файлы Mac, инструменты ограничены буфером и экраном их собственного компьютера.
- Оверлей остаётся на PowerShell + WinForms (один exe без зависимостей); WebView не вводим.
- Один пользователь — один компьютер: выбор компьютера остаётся в приложении и боте только когда их больше одного.
